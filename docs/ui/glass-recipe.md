# 右键菜单毛玻璃：算法与配方（2026-09-10 毛玻璃化定稿；2026-09-12 暗色参数）

> 本文是 `duo/ui/qml/Main.qml` MenuGlassPlate 与 `Style.qml` 毛玻璃令牌
> 的唯一论述文档。代码里不重复这些内容。暗色令牌双值见 DESIGN.md §2；
> 玻璃开关契约见 §6。

## 1. 结构（三明治）

```
MenuGlassPlate（菜单大小）
├─ ① ShaderEffectSource 快照（过采样，1:1）
│     x/y = 快照原点 − 菜单原点（≈ −28）；尺寸 = sourceRect = 菜单 + 2×28
│     sourceItem = canvasRoot（bgLayer 画布 + 色斑 + StackView 页面）
│     live:false；open() 设 sourceRect + scheduleUpdate() 抓一帧
├─ ② MultiEffect（与 ① 同尺寸）
│     blur 0.75 / blurMax 32（二级 0.85；24px 档雾化背景文字）
│     saturation 0.45（二级 0.50，≈ ×1.45/×1.50，对齐胶囊矩阵档）
│     brightness 0.02（二级 0.04）——玻璃体始终比底板亮 ~10 级
│     contrast 0.06（二级 0.10）——浅底中高灰推向白饱和，拉开层阶
│     maskThresholdMin 0.5 + maskSpreadAtMin 0.4
│     maskSource = 过采样坐标系里与菜单同位的圆角白块（透明底）
└─ ③ 描边矩形（菜单大小，radius 12）
      GL：tint 0%（透明）+ 1px 黑 hairline 12%（二级 14%；内边框合成，
      纯白画布上 31 级暗刻）
      软件回退：不透明 menuFill #F7F7F9 + menuFillBorder 10% 黑
```

## 1.5 毛玻璃化（2026-09-10，flash 设计 × Opus 裁决）

用户裁决链：菜单 72% 白 → 与胶囊同步判"奶白"。Opus 终审：**三表面
家族统一 tint 0%**（胶囊/菜单/下巴），可辨性改由光学增益 + 描边承担；
elevation 阶梯从 tint 差改为 blur/sat/bright/contrast/描边五参数阶梯。
勘误存档：flash 对无彩画布上饱和增益的"色晕"效果过度承诺（#F5F5F7
色度 0.008，×1.45 后仍不可感——饱和增益只在彩色底景有价值）；
描边从 10% 上调 12%（纯白画布 25 级 → 31 级暗刻，防溶底余量）。
最坏复核：#FFFFFF 画布上玻璃输出 clamp 255、描边 224，跨边界 62 级
视觉事件；墨字 16.85:1 AAA。矩阵档与视频侧胶囊对齐见
window-experience.md §11 毛玻璃化。

## 2. 硬规则

1. **过采样 1:1**：快照层尺寸 == sourceRect 尺寸 == 模糊层 == 蒙版底板。
   玻璃内容与真实背景像素对位；贴窗边时快照原点内收、显示偏移同步
   补偿（`menuOffX = sx − px`），1:1 恒成立。
2. **28px 边距 > 模糊核触及半径**（0.75×32 = 24px）：菜单可见边缘的
   模糊核心永远采到真实内容，不碰纹理边界。
3. **maskThresholdMin 0.5 是裁切开关**：MultiEffect 默认阈值窗 0..1 =
   恒等映射，蒙版从不裁切（蒙版缺它 = 过采样模糊层整块方形透出，
   即"两层玻璃"）。
4. **maskSpreadAtMin 0.4 是亚像素坡**：smoothstep 阈值窗 [0.1, 0.9]；
   spread 是归一化 alpha 窗，硬 step 在 125%/150% DPR 下相位抖动出毛刺。
5. **autoPaddingEnabled 必须关**（真机 1.25× DPR 实测，2026-09-09）：
   默认 autoPadding 扩大 MultiEffect 绘制边界，蒙版纹理被拉伸到扩大后
   的边界 → 裁切落在比菜单大一圈、带偏移的圆角矩形上，菜单外溢出
   ~14k 像素 = "两层玻璃 + 外层圆角毛刺"；关掉后溢出归零。28px 过采样
   边距使 autoPadding 毫无必要（可见边缘的模糊核心采不到纹理边界）。
5. **坐标 Math.round**：菜单 x/y 取整，两层光栅化（纹理 vs 矢量）的
   半像素相位差断根。
6. **设备像素网格吸附**：分数 DPR（1.25/1.5）下，菜单位置/快照几何只有
   落在设备像素整数上（snapGrid：1.25→4px 格、1.5→2px 格）才能让快照与
   显示两级采样完全对齐；偏网格 1 逻辑像素会重采样出 ~0.5-1 设备像素的
   玻璃内容漂移（"有时候偏移"）。菜单打开期间快照 live 连续采样（首帧
   永不吃旧纹理），关闭即停。
7. **蒙版只做 alpha 裁切**（直角 bug 根治结构）：不要改回方形采样层。
7. **软件回退路径**（!Style.glassBlur，WSL/软件后端）：①②隐藏（不跑
   着色器即免采样），③换不透明 menuFill。

## 3. 配方依据（三轮外审）

- **Opus 审计（方案 A「Win11 Acrylic」，2026-09-09）**：快照源必须含
  画布（原 stack 只含半透明卡片，模糊对透明底凭空合成白雾 = "白光"
  元凶）；色斑需可感知（ΔE>1）玻璃才有折射内容。
- **gemini-3.8-flash 终审（2026-09-09）**：blur 提到等效 24px（15.6px
  打不碎背景文字，透出"脏灰斑"）；黑 hairline（25% 白在浅画布 ΔE<1 =
  无边框）；spread 0.4 亚像素坡；二级浮层 elevation 阶梯（零阴影铁律
  下的分层替代）。
- **毛玻璃化终审（2026-09-10，flash × Opus）**：三表面家族统一
  tint 0%（用户链：72% 白 → 与胶囊同步判"奶白"）；可辨性改由光学
  增益（brightness+contrast，玻璃体比底板亮 ~10 级）+ 描边 12% 黑
  （纯白画布 31 级暗刻，Opus 从 flash 的 10% 上调）承担；饱和增益
  只在彩色底景有价值（#F5F5F7 色度 0.008 不可感——勘误 flash 的
  "色晕"承诺）；elevation 阶梯改 blur/sat/bright/contrast/描边五参数。
- 色斑：同心三层 Rectangle 逼近径向衰减，核心 alpha 0x14–0x16
  （蓝左上 / 绿右下），tint 0% 后色斑直接透出，玻璃有彩可折。

## 4. 迭代史（真机反馈 → 根因）

| 轮 | 反馈 | 根因 | 修复 |
|---|---|---|---|
| 1 | 白光、死白、质感差 | 快照源 = stack（透明底） | 快照源换 canvasRoot + 配方 A |
| 2 | 背景会移动位置 | sourceRect 外扩 16px 塞进菜单大小显示项（缩放 ≈0.8 且贴边后漂移） | 过采样 1:1 |
| 3 | 两层玻璃 + 外层圆角毛刺 | maskThresholdMin 默认 0 = 蒙版从不裁切，过采样层整块透出 | threshold 0.5 + spread 0.4 + 黑 hairline |
| 4 | 仍有两层（threshold 后） | autoPadding 默认拉伸蒙版到扩大边界 → 裁切比菜单大一圈（真机 1.25× 实测溢出 14k px） | autoPaddingEnabled: false（实测溢出归零） |
| 5 | 偶发内容偏移 | 分数 DPR 下菜单位置偏设备像素网格 → 两级采样分数偏移 | snapGrid 网格吸附 + 打开期间 live 采样 |
| 6 | 整体观感"奶白"（与胶囊同步反馈） | 72%/82% 白 tint 把画布方差压进狭小浅色域 = 白皮 | tint 0% 毛玻璃化 + 光学增益 + 12% 黑描边（2026-09-10） |

## 5. 验收标准（真机）

1. 125%/150% DPI 凑近看四角：连续平滑，无台阶、跳点、毛刺。
2. 菜单盖住背景文字：字形彻底粉碎成灰雾，无笔画残影。
3. 纯白/纯空白画布呼出：凭描边 + 玻璃亮度差 0.1s 可辨，
   不溶不粘（tint 0% 后防溶底 = 描边 + brightness/contrast 双保险）；
   暗色画布同验（描边翻白，玻璃略亮于底板）。
4. 蓝绿色斑交界处：淡彩透过玻璃可感（tint 0% 后色斑直接透出），
   非死白非脏灰；暗色下色斑降 25% 后仍可感且不「嗡」。
5. 二级浮层：更亮更实的玻璃板（blur/sat/bright/contrast/描边五参
   阶梯），两级边界清晰，不透视穿透。
6. 玻璃内容与菜单外真实背景严丝合缝（色斑边缘连续），不同落点不漂移。

## 6. 玻璃材质总开关（2026-09-12）

`settings glass_enabled` 实装为「玻璃材质」总开关，三表面统一：

- **QML 菜单**：`Style.menuGlass = glassBlur（着色器能力）&&
  glassWanted（用户开关，ctrl.glassMaterial）`；任一为假走不透明
  menuFill 回退（与软件后端同路径，亮 #F7F7F9 / 暗 #2C2C2E）。
- **会话窗上巴/下巴**：argv `--glass 0|1`（controller `_pin_glass` 每次
  启动 fresh-read settings）；关 = C# 普通材质（见 window-experience.md
  §11 普通材质节）。
- 语义：关玻璃 ≠ 降级——是另一种正式材质，双主题都验收。

## 7. 文字保底光晕（2026-09-14 软光晕定稿；同日硬描边版已废）

**问题**：tint 0% 的玻璃把底景明度原样透上来，菜单飘到深色图标（亮色主题，
实测最坏 ink:glass 2.43:1）或白底图标（暗色，2.27:1）上时，字与底景同调，
字形边界对比度掉到 2.2–2.9:1（11–13px 正文的 AA 是 4.5:1）。厂商对策与数学
推导见 `docs/ui/RESEARCH-LEGIBILITY.md`（结论：固定 tint 只会「奶白」或
无效；Apple 的 luminosity 调整、微软的 exclusion blend 都是逐像素机制，
Qt 侧拿不到）。

**硬描边版为什么被否**（2026-09-14 用户反馈「变粗 + 廉价」+ 两份品味
评审）：`Text.Outline` 不管 alpha 多低，都把字形轮廓整体外扩半个像素——
量到的字形覆盖率面积 +146%（暗墨质量 +18%），13px 正文里足以把 Regular
读成 Medium；边缘还是硬的（浅色玻璃上读成「贴上去的白圈」）。

**实装**：`MenuLabel`（Main.qml）= 两层文字。

```
MenuLabel（菜单里所有玻璃上的文字用它）
├─ mlHalo : 同文字的 Text，color = Style.menuInkHalo（同向低 alpha）
│           layer.enabled = Style.menuGlass
│           layer.sourceRect = 字形 + 8px（让模糊能涂到外面）
│           layer.effect = MultiEffect { blur = menuHaloBlur × menuHaloBlurMax }
└─ mlInk  : 清晰文字（普通光栅路径，零 FBO、零 layer）
```

- **字形零改动**：清晰文字走与普通 Text 完全相同的渲染路径，字重 = 基线
  （探针量：软光晕复用 plain 遮罩，差异 0.0%）。
- **无硬边**：保底层是高斯模糊的剪影，感知上是「玻璃在文字附近自行浑了
  一点」，不是描边。
- **底景同调时不可见**：亮底白晕坐在白玻璃上、暗底黑晕坐在暗玻璃上；
  实测主题画布可见度 1.00（亮）/ 1.05（暗）——常见画面与改动前一致。
- **额度**：亮 38% 白 / 暗 50% 黑（`#61FFFFFF` / `#80000000`），半径
  `menuHaloBlur 0.35 × menuHaloBlurMax 16 ≈ 5.6px`（≈ σ 2.8）。暗色额度
  更高是因为**黑晕在暗玻璃上实测不可见**（画布可见度 1.05），而亮色的
  白晕更易在中间调上被看见。注意 σ 与 α 的分工（`--sweep` 扫描表）：
  σ 只把缓冲**加宽**，几乎不抬字形边界对比；要抬边界只能加 α——与顾问
  "不够就优先加 σ 而非 α"的建议实测相反（那条对"别让光晕变亮斑"成立，
  对边界对比不成立），故暗色按 α 50% 定、σ 沿用单一令牌。
- **只在玻璃路径跑**：`Style.menuGlass` 双闸门，关玻璃/软件回退时剪影层
  `visible = false`（不建 FBO），只剩清晰文字 = 原有回退像素不变。
- 不透明 `controlFill` 上的两个读数（`scaleValueText` / `densityPlaceholder`
  + DPI 输入框）不接线：自身底板已不透明。
- 代价：菜单打开期间每个标签一个小 FBO（≈80×28）＋小半径模糊；关菜单即无。

**选型过程**（可重跑 `docs/ui/probes/menu_halo_candidates.py`）：

| 方案 | 字形覆盖率面积 | 最坏落点字形边界 | 主题画布可见度 |
|---|---|---|---|
| A 硬描边 85%（旧版） | **+146%**（变粗） | 16.7:1（但硬边 → 廉价） | 1.00 |
| B 硬描边 40% | **+146%**（同样粗） | 12.3:1（同上） | 1.00 |
| C 软光晕 2.5px 55% | +0% | 11.0:1 | 1.00 |
| D 软光晕 5px 40% | +0% | 10.2:1（评审：太宽发虚） | 1.00 |
| E 无保底 | +0% | 2.4–2.9:1（字丢） | — |
| **实装：软光晕 2.8px，亮 38% / 暗 50%** | **+0%** | **10.2:1 / 13.2:1**（非
 光晕像素上的中位数）；平铺极端（整块纯黑/纯白垫底，现实不存在）3.9–4.5:1 | 1.00 / 1.05 |

两份品味评审（zai 视觉：图像侧；agy Opus：设计侧）均选软光晕，Opus 额外
给了铁律 8 的例外条款与参数带上限（已写入 DESIGN.md）。

**契约测试**：`tests/test_menu_legibility.py`（纯 Python 复算配方：实测
最坏落点无光晕必低于 AA、满覆盖核心达 AA、半覆盖边界守住 4.0、主题画布
上不可见、光晕方向随墨色翻面、额度不超预算）；`tests/test_qml_app.py` 锁
MenuLabel 双层结构、令牌值与六枚菜单的接线（含「不得再用 Text.Outline」）。

**出图**：`docs/validation/assets/menu-legibility-before-after.png`
（上亮下暗，左无保底右实装，2× 放大）与 `menu-halo-probe.png`（三档底景

**真机复核项**：玻璃合成的观感、MultiEffect 模糊在 1.25×/1.5× DPR 下的
实际半径（调 `menuHaloBlur/Max` 一个数）、以及软光晕在彩色底景上是否

## 8. egui 实装（2026-09-17 快照模糊路线；2026-09-18 暗色光学调优）

egui/wgpu 侧没有 QML `MultiEffect` 的实时层模糊，采用**单帧快照 + CPU 模糊 +
纹理**路线；参数针对桌面菜单视觉美感与可读性深度调优（主/二级菜单统一 σ8；
亮色 brightness +0.02 / contrast +0.06 / sat ×1.45；暗色微底色 + 柔和高光滚降 +
饱和度 ×1.65 + 纵向光泽，杜绝纯黑死底与雾蒙蒙；hairline 亮 12% 黑 /
暗 14% 白、r12）。

**状态机与纹理生命周期（2026-09-18 完善）**：
- **ShapeIdx 预占底位（首帧零延迟垫底）**：`glass_underlay` 在菜单闭包开头
  通过 `ui.painter().add(Shape::Noop)` 预占 ShapeIdx，并在 `glass_record_main`
  建好贴图后通过 `ui.painter().set(idx, Shape::image(...))` 原地更新。彻底解决
  「首帧先画控件后算贴图导致的 1 帧背景空白」边界问题，即使首次打开第一帧
  也能将贴图垫在所有控件之下。
- **快照缺失边界场景防护**：移除了「快照未就绪即 return 放弃弹窗」的旧逻辑，
  呼出时若快照暂缺，菜单正常展开，同步触发 `Screenshot` 与 `request_repaint()`，
  下一帧（~16ms）快照落地自动无感填补；闲时重截与快照失效时均主动推进重绘。
- **全链路几何尺寸锁（128px 宽 / 4px 边距 / 120px 内部）**：
  - egui 默认 `spacing.menu_width = 400.0`。在 `sync_visuals` 中全局锁定
    `spacing.menu_width = 128.0` 与 `spacing.menu_margin = Margin::same(4)`。
  - 菜单内部所有控件统一定宽 `MENU_INNER_WIDTH = 120.0`，外扩 4px 严丝合缝 128px，
    彻底消除尺寸发散与抽搐。
- **全透明穿透视觉契约**：
  - `glass_enabled` 时，`window_fill = TRANSPARENT`、`window_stroke = NONE`、
    `popup_shadow = NONE`，框架原生灰底完全清除，全由毛玻璃贴图呈现。

**暗色模式消除「冷峻感」与光学底光微抬（2026-09-18）**：

用户真机反馈：「现在的版本在背景很暗的时候，会让其压得更暗，有一种冷峻感，这样不是很好，需要优化一下。」

**根因推导（对比度轴心错位）**：
- 原公式采用传统中间灰轴心 `(c - 0.5) * (1.0 + contrast) + 0.5 + brightness`。在浅色模式下画布 ~0.94，对比度与正亮度向上推至 ~0.98（"玻璃体始终比底板亮 ~10 级"）；
- 但在暗色模式下，底板画布为 `#121214`（28 / 255 ≈ 0.11）。由于 0.11 远低于 0.50，对称对比度运算将 `-0.39` 进一步下拉放大，叠加负 brightness 后导致原本 28 级的底色被强行压向 **19 级（甚至 14 级）**！
- 违背了 §5.3 的终审验收标准**「暗色画布同验（描边翻白，玻璃略亮于底板）」**与 `theme.rs` 标定的暗色玻璃目标阶梯 34/35 级，使深色菜单变成了沉闷凹陷的冷黑深坑（「冷峻感」元凶）。

**物理与光学修正（Pivot 0.11 + 单侧对比扩张 + 底光微抬）**：
- **轴心对齐暗色底景**：`pivot = 0.11`。低于 0.11 的超深黑区域不作负向乘积下拉，仅接受平移微抬；高于 0.11 的卡片与高光正常展开对比度；
- **底光温和微抬（`brightness: +0.025`）**：底景 28 级平滑浮动至 **34 级**（`menu_glass` 设计值），还原真实物理毛玻璃在暗光环境下的菲涅尔散射与环境反射；
- **纯光学 0% Tint**：彻底抛弃人工深灰 tint 染色，背景卡片（粉、蓝、紫、棕）温润透光，色斑与折射晶莹剔透；
- **柔和高光滚降（`highlight_ceiling: 0.40`, `highlight_slope: 0.15`，三次 Hermite 软膝 ±0.05）**：只收 >102 级的高光顶端，纯白穿透收敛在 ≤128 级（白字 ≈4:1，接近 WCAG AA）；**≤89 级内容 100% 零干预**，89-115 级软膝平滑过渡（值+斜率双连续，膝外输出与硬拐点完全一致）——中间调结构完整，这是玻璃透明感的来源。迭代教训（2026-09-18 真机）：0.22/0.04 深压档把 56-255 级全压进 ~9 级窄带，亮度结构归零，用户判「糊成一团死灰板、毫无美感」——压暗只能收窄高光顶端，绝不可吃掉中间调动态（Apple vibrancy 同构：材质是设计过亮度带的结构保留面，不是压黑矩形）。agy opus-4.6 终审（2026-09-18）：白底输出 127 级，恰在 ≤128 约束的帕累托边界，无放宽空间（0.42/0.18 → 132 违约）；硬拐点导数跳变 6.7× 会 banding → 软膝实装（注意：smoothstep 值混合在 R<L 区有非单调凹陷，必须用 Hermite）；饱和度 ×1.38 复核维持。

**去「雾蒙蒙」：Liquid Glass 质感增强（2026-09-18，Apple/ColorOS 17 理念）**：

真机反馈「雾蒙蒙的不好看」。根因：σ6.5 只糊一半，半糊残影=脏雾；模糊洗掉的
彩度没有回注（灰=雾）。

- **Apple Liquid Glass**：重模糊只取样色不取样形 + 饱和度回注 + 顶部镜面棱线
  （specular rim）；
- **ColorOS 17 Fluid**：轻透明磨砂 + 表面光泽（Condensed Light）；
- **实装**：暗色 σ 6.5→**8**（一二级统一；初版 11 被真机判「过糊缺细节」回调，
  顶部棱线同批反馈过重已移除）、饱和度 ×1.38→×1.65（Unit 4 ×1.60）、纵向光泽
  渐变 `sheen 0.045`（顶 +4.5%/底 −4.5%）。亮度带合同不变（白底 ≤128 级，
  可读性底线仍在）。

**菜单行可读性与悬停洗色（2026-09-18 修复）**：

用户真机反馈：「右键菜单栏之中 固定比例的二级菜单“横屏竖屏”是会的色，现在看不清，以及有些地方的字体有点灰导致看不清，直接用白色即可；然后比如选中 固定比例之后，这个地方背景会变亮导致 “固定比例这几个字看不清，也需要优化”」

1. **二级小节头纯白化与字号提亮**：
   - `menu_caption`（"横屏"、"竖屏"、"上巴"、"下巴"）在暗色模式下一律直出 `Color32::WHITE`，字号从 11.0px 提至 12.0px 强化笔画可读性，彻底消除灰字在深色背景上的可读性坍塌；
   - 菜单文字与子菜单箭头（"⏵"）同步保障暗色纯白（`fg_stroke.color = Color32::WHITE`）；
   - 比例示意矩形轮廓（`menu_aspect_item`）暗色提纯至 78% 白（`rgba(255, 255, 255, 200)`）。

2. **悬停洗色物理预乘校正（解决「固定比例」选中泛白失真）**：
   - **根因推导**：`ecolor::Color32::from_rgba_unmultiplied(255, 255, 255, 20)` 在构造时会执行非线性伽马反算 `gamma_u8_from_linear_f32(0.07843) = 79`（0x4F）。而 egui / wgpu 着色器执行的是线性预乘合成 `src_rgb + dst_rgb * (1 - a)`。由于源 RGB 被抬升为 79（0.31），在 34 级底色上叠加后直接飙升至 **110 级**，呈现出一块死白不透明的厚重灰块，致使文字边界被彻底吞噬冲淡；
   - **物理预乘修正**：改用精确线性预乘通道 `from_rgba_premultiplied(12, 12, 12, 20)`（hover）与 `(24, 24, 24, 36)`（press）。底色 34 级温和浮动至 **43 级**（+9 级轻柔微抬），既清晰指示选中态，又完全保留毛玻璃的晶莹通透；
   - **超高可读性**：纯白文字（252+ 级）对 43 级底色形成 **45:1 极限对比度**，远超 WCAG AAA 规范，彻底根除字迹模糊；
   - **零溢出规整几何**：`expansion = 0.0`，`corner_radius = 8`，悬停色块严丝合缝嵌于 32px 行高之内，彻底消除 1px 外溢穿帮与行间粘连。

**限制说明**：
- 二级子菜单玻璃为模糊底景（与 QML 架构一致）。
